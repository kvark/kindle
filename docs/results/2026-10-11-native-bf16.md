# Native BF16 foundation

October 11, 2026. Part of the [backend performance plan](../backend_training_performance_plan.md).
Kindle training remains stopped. This qualifies storage, conversion, matrices
and explicit dense/pointwise training regions, **not a complete mixed-precision
Kindle learner or an end-to-end speedup**.

## Implemented

- Naga [c9fd6a85a](https://github.com/kvark/wgpu/commit/c9fd6a85a87034ecb5a784611c6f90a14d8d50ce):
  distinct BF16 scalar/literal, native `wgpu_bfloat16` extension, checked
  capabilities/conversions and SPIR-V encoding. Ordinary arithmetic widens to
  F32; unsupported BF16 arithmetic, shader IO and other backends reject it.
  This is the user's compiler fork, not upstream WebGPU BF16 support. The user
  explicitly approved the fork commit; no upstream wgpu PR was opened.
- Blade [PR407](https://github.com/kvark/blade/pull/407), `b52965b`: query/enable
  Vulkan BF16 storage/conversion and BF16/F32 cooperative shapes. Dot products
  remain disabled; Metal/GLES retain unsupported capabilities. Pins the Naga
  fork. Draft, not merged or installed in Kindle.
- Meganeura [PR250](https://github.com/kvark/meganeura/pull/250), `18be13c`:
  two-byte internal BF16 buffers, explicit narrowing /
  widening, three matrix layouts with optional F32 addends, F32 accumulation,
  and straight-through F32 master gradients. Unsupported consumers reject
  explicitly. Forward BF16 operands are widened for the existing F32 backward
  path; **backward computation and connected activation regions are not yet
  reduced precision**. Strict-F32 graphs are not automatically narrowed.

The 5080 driver's plain `OpFConvert` narrows toward zero. Meganeura instead
implements nearest-even rounding with GPU integer operations before casting
an already representable F32 value to BF16. This is not CPU conversion or a
CPU learner. A proposed global SPIR-V rounding decoration was removed before
GPU execution: its allowed-use restrictions do not cover arbitrary temporaries.

## Connected-region follow-up

Meganeura PR250 now includes `f979fa9`: explicit matrix stores and pointwise
conversion boundaries fuse, retaining BF16 buffers between supported kernels.
Pointwise arithmetic widens inside the kernel and rounds once on output.
Shared/observable F32 values remain; no implicit precision change. Opt-in
`bf16_matrix_gradients` uses BF16 derivative operands for explicit BF16 forward
matrices, with F32 accumulation, parameter gradients, master weights and Adam
state. Default backward still widens to F32. BF16 reshapes now correctly retain
F32 gradient views.

One additional guard passes in9.76s child time: all eight focused tests pass,
including18 new F64-referenced reduced-gradient cases (three layouts, optional
addend, derivative scales1e-20/1/1e20), both fused/unfused connected checks and32
synthetic Adam updates. A two-layer clamped-activation fixture's loss falls
.16861932→.03437764; parameters and both moments stay finite. This is a small
synthetic network, not a Kindle full update or game-learning result.

CPU checks pass27 schedule/10 autodiff tests, the portable BF16 oracle/coverage
checks,16 pointwise storage and12 matrix store/layout/addend shader combinations,
BF16 views and protected outputs. All-target/all-feature Clippy passes.
The fixture uses28 dispatches with all fusion disabled versus17 enabled; this
includes existing fusion, not an isolated BF16 speed measurement. No timing
or universal reduced-storage coverage claim. Binary `7fefe416`, immutable source
archive and `bf16-regions-queue` retain the exact tested candidate.

## Failures retained

The first Meganeura GPU test matches numerical expectations but fails its
guard: odd BF16 lengths produce 2,070- and 34-byte `vkCmdFillBuffer` calls,
violating the multiple-of-four requirement (VUID00028). Physical allocations
already have 16-byte padding. The fix rounds only the clear span to whole
words, within that allocation; the corrected guarded test passes. No tolerance
change or retry of unchanged source.

CPU preparation also catches new-enum exhaustiveness errors, missing implicit
cooperative capabilities, an initially accepted BF16 equality, and invalid
test fixtures/tooling. Later matrix preparation catches a misspelled training
mode, missing test-only binding assignments, and cooperative loads under
nonuniform control flow. The shader now executes cooperative loads/products
uniformly and lets one subgroup store, as existing kernels do. The full-stack
check catches one remaining wgpu texture-kind match, now explicitly unreachable
after Naga rejects BF16 image types. Failed test commands and Clippy findings,
the negative test's overly specific panic expectation, snapshots and journals
remain; none is counted as a passing check.

PR250's first CI fails because the new conversion operators were omitted from
the oracle coverage registry (the other163 oracle tests pass on each platform).
`bdf4fe6` adds their portable reference/master-gradient test and registration.
Expanded CI remains pending. Connected-region preparation also retains a missing
Cargo PATH, two missed search call sites, a Rust borrow error, and a fixture
assertion that overlooked a shared ReLU activation needed by backward. No GPU
failure or tolerance relaxation follows: that shared value correctly remains
F32; the clamped fixture exercises the intended removable boundaries.
