## What is implemented

`bf16_dense` selects ordinary dense products before autodiff in posterior,
imagination, world/behavior gradients and slow value. Native BF16 operands and
storage use FP32 accumulation. Supported pointwise boundaries fuse conversions,
with FP32 arithmetic. Parameters, optimizer state, sensitive reductions/losses,
convolution and grouped RSSM products remain FP32. Live acting is unchanged.
The control retains historical Auto inference and F16 training permission;
the candidate's unconverted products use native F32. Auto remains the default.

Each of the five learner sessions contains native BF16 products. CDP world
gradients contain424 BF16 matrix dispatches and213 typed pointwise dispatches,
but still262 standalone casts; total dispatches increase to4,424. This is not
whole-network reduced storage. Unsupported hardware rejects the explicit
option instead of silently falling back or using a CPU learner.

The first16x16 BF16 kernel duplicated work across subgroups. A qualified32x32
tile distributes four hardware tiles across subgroups and stages32 K elements.
The first full integration measured156.40/66.90 ms; the tiled path measures
149.66/66.55 ms before the final pin refresh above. No parameter/model-size,
exploration, replay-ratio or image-detail change. Convolution PR248 and layout
PR249 are not stacked into these measurements.
