## Critical / High

### C-1. Win-classifier trains on all-zero latents — `value_z` is never uploaded
`kindle/src/agent.rs:5894-5947` (`value_replay_step`). The balanced win/loss
batch is written into `value_z_scratch` (line 5912) but
`set_input("value_z", …)` is never called; the only `set_input("value_z")`
in the file writes zeros (`wm_predict`, lines 6383/6388). The classifier head
reads the `value_z` graph input (agent.rs:3292/3299), so with
`value_head_train_coef > 0` every BCE step fits labels against z = 0:
`fc1.weight` receives exactly zero gradient and the head converges to the
label base rate. The planner's `planner_value_alpha` scoring (weights pulled
at 9695-9716) then contributes random-projection noise, not value. One-line
fix: add `self.wm_session.set_input("value_z", &self.value_z_scratch);`.

### C-2. k-step WM session clobbers the trained world model with a random-init lineage
`kindle/src/agent.rs:5753-5868` (`wm_kstep_step`). `wm_kstep_session` gets its
own random init (3814-3833) and is never seeded from `wm_session` — not at
construction, not per call, not in `load_state` (8653). Yet every
`wm_kstep_step` copies kstep's six mean-dynamics params **into** `wm_session`
(5855-5867). First firing replaces the trained WM trunk with
(random init + one gradient step); thereafter all online single-step WM
training between kstep firings is discarded at each sync, and after
`load_state` the restored WM is clobbered too. The "Synced *back*" comment
implies a forward wm→kstep sync that does not exist.

### C-3. `rollout_length > 1` panics on the first `act()`
`kindle/src/agent.rs:4501-4513, 4064-4070`. The policy graph's `action` input
is `[batch_size × rollout_length, MAX_ACTION_DIM]` (3489), but `act()` feeds
`action_token_scratch`, sized `batch_size × MAX_ACTION_DIM` (4068), and
meganeura's `upload_buffer` asserts exact byte-size equality
(runtime.rs:2867). Same mismatch for `action_mask` under `use_ppo` (4511),
and in e2e mode `obs_token_scratch`/`task_scratch` mismatch the WM session in
the other direction. The entire A2C/PPO rollout-buffer feature is currently
unusable.

### C-4. `planner_param_buf` undersized — panics for common shapes
`kindle/src/agent.rs:3908`. Allocated as `hidden_dim²`, later sliced to
`latent_dim·hidden_dim`, `MAX_ACTION_DIM(=18)·hidden_dim`, `latent_dim·vh`,
and `num_options·MAX_ACTION_DIM` (5864, 9639-9707) with no resize. Any config
with `latent_dim > hidden_dim` (e.g. the latent_dim=256 ARC configs) or
`hidden_dim < 18`, combined with `planner_horizon > 0` or `wm_kstep_k > 1`,
panics with a slice out-of-range at the first weight refresh.

### C-5. With `use_adam`, every `act()` corrupts the Adam state
`kindle/src/agent.rs:4543-4555`. `act()` runs the training graph with lr = 0,
but meganeura's AdamUpdate kernel still runs each `step()`: it increments
`adam_step` and updates the m/v moments from the current gradients
(runtime.rs:3445-3470; lr only scales the parameter delta). The staged
act-time loss is fake (`value_target = 0` pulls V(s) toward 0; the entropy
branch emits real gradients), so ≥50% of all moment updates come from a bogus
objective: m biased toward shrinking the value head, v inflated (shrinking
effective step size), bias-correction advancing twice per env step. SGD
configs are unaffected.

### C-6. E2E entropy regularizer trains a phantom parameter copy — zero effect on the acting policy
`kindle/src/policy.rs:680-720` (`build_policy_graph_e2e`). The entropy branch
re-instantiates the policy by name (`nn::Linear::new(&mut g, "policy.fc1", …)`)
assuming name-based weight sharing, but meganeura's `Graph::parameter`
unconditionally creates a new node with its own buffer and gradient (no
CSE/name-dedup in the optimizer). Copy A (used for sampling and CE loss)
never receives the entropy gradient; copy B receives only the entropy
gradient and is read by nothing. Every `end_to_end_encoder=true` run has no
entropy regularization despite the whole runtime `entropy_beta`
input/annealing machinery (agent.rs:6176-6185). The sibling graphs do it
right (`build_ppo_policy_graph_e2e`:1015, `build_kl_policy_graph_e2e`:833
reuse the same NodeIds) — same fix applies.

### C-7. CI's GPU test step can never fail — and it's the only place those tests run
`.github/workflows/ci.yml:50-54` has `continue-on-error: true` on the step
running `opt_parity`, `canaries`, `wm_direction`, and `stability` — all of
whose tests are `#[ignore]`d and run nowhere else. The README's "Meganeura
Confidence Plan" Tiers 2/3/5 are unenforced: a regression that breaks e-graph
parity or XOR convergence produces a green run. (Demonstrated concretely
during this audit: all four suites failed with a missing Vulkan driver and
the pipeline would still have passed.)

### C-8. Every kindle-gym example violates the post-action observation convention
`Agent::observe` (agent.rs:4685-4694) requires the observation that
*resulted* from the action (`act() → env.step(a) → observe(o_next, a)`).
Every example instead captures `env.observe()` **before** `env.step` and
passes that pre-step observation: `bench_envs.rs:97-106`,
`multi_env.rs:137-146`, `stability_1m.rs:93-102`, `wm_probe.rs:46-55`,
`taxi.rs:38-47`, `taxi_credit_probe.rs:58-77`, `l1_long.rs:53-79`,
`l1_learned_term.rs:73-111`, `l1_alpha_sweep.rs:92-120`, and four loops in
`l1_diagnostic.rs`. The WM learns `enc(o_{t-1}) + a_t → enc(o_t)` (each
transition paired with the *following* step's action) and the policy trains
`a_t` against the latent of a state it wasn't chosen from.
`tests/stability.rs:54-64` does it correctly, with a comment citing the
convention — the examples are stale, not an alternate convention. All
historical benchmark numbers from these examples measured a mis-specified
learning problem.

### C-9. Goal-reaching envs punish success: auto-reset runs before the homeostatic update
The homeo reward is computed from the `StepResult` filled **after**
`reset()`:
- `kindle-gym/src/mountain_car.rs:95-101` — reaching the goal reports the
  post-reset worst drive state (penalty 0.8); hovering at 0.49 forever is
  reward-optimal.
- `kindle-gym/src/acrobot.rs:184-190` — success is the single most-punished
  transition available (penalty ≈ 2.89 vs ≈ 0 for hovering under the bar).
- `kindle-gym/src/taxi.rs:166-180` — successful dropoff reports the next
  episode's Manhattan distance; sitting on the destination without pressing
  dropoff yields penalty 0 indefinitely.
- `kindle-gym/src/cart_pole.rs:117-119` — inverse sign of the same bug:
  failure resets θ to 0.01 so the failing step reports the drive *satisfied*;
  falling is nearly free.
Fix: run `update_homeo()`/build `StepResult` before the auto-reset (or report
the pre-reset homeostatic state on terminal steps).

### C-10. README quick-start calls a nonexistent API
`README.md:304` (`agent.train(Wrapped(env), steps=10_000)`): `PyAgent` has no
`train` method (never existed per git history); the real API is
`agent.run(env, steps)`, which also obviates the hand-rolled `Wrapped`
adapter. `CHANGELOG.md:76` repeats the phantom API.

### C-11. Python example harnesses corrupt their own results
- `python/examples/atari_batch.py:138-152` — the homeo channel is symmetric
  (`-max(0, |value|-tol)`): a Pong point won and a point lost yield the same
  −0.5 penalty; in the default config this is the only reward channel, so the
  agent is trained to avoid scoring events of either sign.
- `python/examples/arc_agi3_batch.py:547,604` — `--encoder cnn_dqn` never
  calls `set_visual_obs` (checks `== "cnn"` only): the CNN-DQN encoder sees
  all-black frames for the entire run. (`arc_agi3_multi.py` checks correctly.)
- `python/examples/gym_extrinsic.py:503-505` — LR-drop-on-solve computes
  `args.lr_policy / drop` where `--lr-policy` defaults to the sentinel `0.0`,
  so solve detection sets the policy LR to exactly 0 and freezes learning.
- `python/examples/arc_agi3_multi.py:299-311,404` (and
  `arc_agi3_batch.py:373`) — when the sampled action isn't in
  `available_actions`, a substitute is executed but `observe()` is fed the
  *original* index: the policy is credited and the WM trained on actions that
  were never taken. `set_action_masks` exists for this and is only used by
  `arc_agi3_grpo.py`.

## Medium

### Core (`kindle/src/agent.rs`)
- **M-1** (4380-4388): L1 option-policy and option-value train on the
  option's **end** state instead of its start state; the captured
  `lane.option_start_z` exists but isn't fed. Advantage degenerates toward a
  differenced return signal and option choice is credited at the wrong state.
- **M-2** (4202-4245): `mark_boundary`/`switch_lane` don't clear
  `planner_queue` — after an episode ends (or the lane switches games) the
  remaining planned actions from the dead episode still execute.
- **M-3** (4290-4298): `act()` ignores `pending_boundary` — the first action,
  value baseline, option resample, and goal-EMA of each episode use the
  previous episode's terminal latent; the boundary transition's advantage
  `r₀ − V(crash)` is systematically mis-signed. (E2e logits/value unaffected;
  option machinery still affected.)
- **M-4** (4318,4385): the option session is driven via
  `set_learning_rate()`, which in meganeura switches the session to SGD —
  `use_adam` never applies to L1, contradicting the config doc (265-272).
- **M-5** (7341-7370): `use_ppo` with `n_step == 1` silently zeroes the policy
  gradient — `advantage`/`old_prob_taken` are never staged on that path and
  `act()` zeroes `advantage` each step; the policy freezes with no error.
  The "requires policy_update_interval > 1" constraint is prose only.
- **M-6** (7787-7822): KL-PPO's `old_logits` is only staged in
  `policy_step_rollout_batch`; with `rollout_length == 1` the trust region is
  silently KL-against-uniform (device buffer holds the zeros `act()` wrote),
  despite per-transition logits being stored in the buffer for this purpose.
- **M-7** (9403): BC-from-planner reads `all_actions[best_row * k]` but the
  layout is `[batch, k, inner_iters]` — with `inner_iters > 1` (always, in
  option-aware planning) SIL is fed another row's action with synthetic
  positive reward.
- **M-8** (8758-8777): `train_coord_head` recomputes hidden activations from
  the **post-step** latent while reusing μ/sample cached from the pre-step
  forward — misaligned (state, action) credit, worst across episode
  boundaries.

### Support modules
- **M-9** (`buffer.rs:500-536` + `credit.rs`, caller agent.rs:6946-6971): the
  credit assigner's training input is the most recent window but the
  contrastive target is computed for different (hi/lo surprise) windows —
  input and label are uncorrelated row-for-row; `flatten_history_at`, which
  would fix it, is dead code.
- **M-10** (`credit.rs:85-87,172-187`): double-softmax — predictions trained
  in probability space are softmaxed again at use time, bounding the
  attribution ratio between any two steps by e ≈ 2.7 and flattening credit
  toward uniform; the `last_h_eff_l1` diagnostic is nearly constant.
- **M-11** (`rnd.rs:122-130`, `diayn.rs:119-128`, `coord.rs:165-174`): CPU
  two-layer heads update `w2` in place inside the same loop that uses it for
  the hidden-layer gradient — backprop uses post-update weights; a persistent
  O(lr·d²·h) gradient bias at these heads' large LRs.
- **M-12** (`reward.rs:208-217`): the order reward compares plug-in entropy at
  512 vs 64 samples over 256 buckets — the small-sample bias differs 8×, so
  diverse-but-stationary behavior earns a constant positive reward; the
  stationarity unit test only exercises 8 buckets and can't see it.
- **M-13** (`policy.rs:378-400,943-954`): the action-mask offset of −60 is
  justified by a ±50 logit clamp that was removed — a strongly committed
  policy can regain non-negligible probability on masked actions.

### Python bindings
- **M-14** (`python/src/lib.rs`): Rust panics cross the FFI boundary as
  `PanicException` (a `BaseException`) rather than `ValueError` — e.g.
  `num_actions > MAX_ACTION_DIM`, wrong-length inputs to `set_action_masks`
  / `set_extrinsic_reward` / `set_visual_obs`; harness `except Exception`
  blocks won't catch them.
- **M-15** (`python/src/lib.rs:268-285`): per-call obs length is never
  validated — long obs silently truncate at `OBS_TOKEN_DIM=64`, short obs
  silently zero-pad; the constructor's `obs_dim` is effectively unused for
  tokenization.
- **M-16**: no `py.allow_threads` anywhere — the GIL is held across all GPU
  work, stalling any thread-based env/logging.
- **M-17** (`agent.rs:6117` + `lib.rs:1626`): `set_intrinsic_progress`
  silently no-ops when `extrinsic_reward_alpha == 0`; `arc_agi3_grpo.py`
  only sets alpha > 0 for other flags, so `--progress-*` coefficients can be
  silently dropped.
- **M-18** (`arc_agi3_grpo.py:1284-1298`): the frontier/stagnation random
  action override happens after `act()`, so `last_prob_taken` (π_old) no
  longer matches the trained action — wrong importance ratios under
  `--use-ppo`/KL-PPO.
- **M-19** (`lib.rs:1386-1388`): a too-short per-lane homeostatic list is
  silently padded with empty lists — trailing lanes lose their homeo signal
  with no diagnostic.

## Cross-cutting themes

1. **Silently-vacuous training paths.** meganeura sessions keep zeros for
   inputs that are never staged, and duplicate same-name parameters instead
   of sharing them. C-1, C-6, M-5, M-6, and the `reward_target` gap are all
   instances. A cheap structural guard would catch the whole class: a debug
   assert that every graph input was staged at least once before the first
   `step()`, and a meganeura-side error (or dedup) for same-name parameters.
2. **Config combinations that panic or no-op without construction-time
   asserts**: `rollout_length > 1` (C-3), `use_ppo && n_step == 1` (M-5),
   `use_kl_ppo && rollout_length == 1` (M-6), `end_to_end_encoder &&
   n_step == 1`, `use_adam` on the option session (M-4),
   `latent_dim > hidden_dim` with the planner (C-4). Validating
   `AgentConfig` once at construction would convert all of these into
   immediate, explicit errors.
3. **Harness bugs corrupt reported results** on both the Rust (C-8) and
   Python (C-11) sides — worth a single shared reference harness per
   language that examples copy.
4. **CI blind spots**: the GPU step can't fail (C-7) and `python/` escapes
   all lint gates. Given lavapipe runs these suites in ~4 minutes, promoting
   them to a hard gate is feasible.
5. **Docs drift**: several load-bearing docs (README API/quick-start,
   failed_experiments.md, milestone table) actively mislead.
