# Dreamer + predictive representation kickoff

Work began 2026-09-05 at 08:45 UTC on branch `dreamer-jepa-kickoff`.
This is an experiment report, not a second roadmap. The authoritative direction
is [the project plan](../kindle_single_life_dreamer_plan.md).

## Recovery and audit

The starting checkout was clean at `95c222d`. The separately rebased
`exp/dreamerv3-baseline-12m` branch at `26a34aa` contained missing work: landed
Meganeura/Blade fixes, full-recurrence row microbatching, large-actor gradient
checks, lifecycle canaries and stricter score/training summaries. Comparing
the two tips directly avoided treating their duplicated/rebased history as new
implementation. The code is recovered in kickoff commit `8d8a0dc`.

The evidence was ahead of both plans. Three 12M Pong runs had completed, with
final-window scores −4/+6/−2, and a local pinned upstream 1M control existed.
The plan now distinguishes completed evidence from actual remaining work.

The retained architecture is compact and appropriate for this gate: a native
frozen visual frontend, categorical RSSM, sequence replay, imagined actor/critic
and categorical environment adapters. Its most consequential gaps are temporal
prediction/control validation, synchronous acting/learning, lifetime replay and
exact recovery. A larger video encoder or swarm service would not address those
gaps by itself. Unused ARC dependencies and obsolete README recipes were removed.

## Synchronization was the first bottleneck

Hardware: RTX 5080, 16 GB, device ID `0x2c02`, driver 595.71.05. One GPU-heavy
process runs at a time. Backend pins are Meganeura `bd6be088` and Blade `b208f3b1`.

The canary uses size12m, B16×T64, full BPTT 64, world row microbatch 4,
18 actions, frozen synthetic observations and eight direct learner updates.
It excludes DINO and environment costs. Medians below discard the first two
updates. Configurations are printed in the companion `.log` files.

| Stage | Original mapped-host reads | Batched cached reads |
| --- | ---: | ---: |
| Replay sampling | 0.00073 s | 0.00076 s |
| Posterior inference | 0.286 s | 0.231 s |
| Imagination/targets | 3.800 s | 0.304 s |
| World training | 0.933 s | 0.846 s |
| World synchronization | 1.894 s | 0.014 s |
| Behavior training | 0.030 s | 0.026 s |
| Behavior synchronization | 0.472 s | 0.003 s |
| Total update | **7.421 s** | **1.425 s** |

The confirmation is a **5.21×** update speedup. The first paired measurement was
8.429→1.428 s (5.90×), illustrating variation in the slow read path. Do not
extrapolate either ratio directly to end-to-end game throughput.

`Session::read_param` and `read_output_by_index` were copying directly from
CPU-visible GPU allocations without CPU caching. Reusing the backend's existing
batched `read_params` and a small reusable `Memory::Download` output buffer
removed the dominant host stalls. No optimizer or precision change was needed.

Verification compared **all 241 checkpoint tensors byte-for-byte by name**:
164 world tensors, 66 behavior tensors and 11 slow-value tensors, including
optimizer moments. Every tensor, the metadata and all eight world/behavior
reports matched exactly. Safetensors container headers can differ in key order;
file-level byte comparison is therefore not a tensor-equivalence check.

A second pass extends cached readback to batch/live posterior outputs and drops

### Complete dispatch capture, isolated instrumentation

An isolated Blade worktree at the same `b208f3b1` revision changes only
`limits::PASS_COUNT` from 1,000 to 100,000. A separate Kindle worktree at
`1efd183` points to it; production dependencies remain pinned and unchanged.
This captures all 76,016 world dispatches. All 241 saved tensors, optimizer
metadata, scalar metadata and eight reports remain identical to the normal
cached-readback control.

The enlarged-capacity build measures 155.60 ms ordinary GPU and 222.26 ms wall
for the world gradient, versus 447.67 ms GPU and 531.35 ms wall under complete
per-dispatch instrumentation: **2.39× wall perturbation**. Timed intervals include
inter-pass barriers; instrumented family shares are not normal-runtime shares.

| Dispatch family | Count |
| --- | ---: |
| Pointwise | 31,894 |
| Data movement | 28,316 |
| Normalization/reduction | 8,384 |
| Matrix | 7,422 |

About 79% are pointwise/layout operations. Inspecting the pinned compiler shows
that one generically labeled `Relu` pipeline actually implements forced identity
copies. It accounts for **11,264 dispatches and 7.82 GB of copied output per
microbatch**. Kindle's slice/concatenation helpers request these copies, including
repeated full grouped-weight tensors. The next small candidate is removing
redundant materializations under full numerical/learning checks, followed by
grouped RSSM/layout fusion. Do not interpret the generic shader names as the
model's activation functions. Driver-reported local-memory statistics contain
implausible values and are not used to infer spills or occupancy.

## Causal objective, not renamed reconstruction

The new head predicts frozen `u[t]` from `h[t]` before the observation enters
the posterior. Its target is stop-gradient; reset arrivals are excluded.
The feature event dimensions are summed and B×T averaged, matching the existing
reconstruction scale convention. A zero reconstruction coefficient removes
that head's parameters. The future head is used by diagnostics whenever enabled,
including auxiliary runs, and reset forecast errors are excluded from summaries.

The hardware suite passed nine tests, including action/observation-conditioned
learning, causal prediction, gradients through previous observations, reset
masking, predictive checkpoint round trips, control and predictive microbatch
equivalence, full-size actor gradient coverage, cached readback and DINO parity.
The first new future-loss test exposed a scalar-broadcast assumption in the
mask normalization; explicit row-shaped constants fixed it before game trials.
See `runs/kickoff-gpu-suite.log` and the earlier diagnostic logs.

## Initial native objective pilot: head-structure confound

These first predictive runs used a global MLP, while reconstruction used a
spatial decoder. Matching the trajectory and approximate parameter count did not
isolate the objective. A subsequent audit caught this confound. The current
implementation reuses the spatial decoder for both and matches downstream
initialization; only the predictive trunk omits current posterior stochastic
inputs. Its checkpoint head revision is `spatial-deterministic-v1`. The retired
MLP checkpoints require kickoff source `3073726` or earlier and are rejected
explicitly by the new runtime. No obsolete second head implementation is retained.

Training: GridWorld, seed 0, all four actions including border no-ops, 10,000
forced-random actions, size1m, BPTT 64, B16×T64, ratio 256, world learning rate
1e-3, behavior rate 1e-4, no warmup, all other Dreamer losses unchanged. These
are diagnostic native rates, not the Atari protocol. All variants receive the
same trajectory. Frozen evaluation uses 10,000 greedy actions, not learning.

| Objective | Trainable parameters | Updates | Training food | Frozen food |
| --- | ---: | ---: | ---: | ---: |
| Reconstruction 0.25 | 836,899 | 2,230 | 188 | 2,500 |
| Future 0.25, no reconstruction | 828,707 | 2,230 | 188 | 2,500 |
| Reconstruction + future, both 0.25 | 1,077,859 | 2,230 | 188 | 2,496 |

Reconstruction and prediction-only attain the native task's 50 rewards per
200-action episode; the auxiliary attains 49.92. This retains simple-task control after removing posterior reconstruction;
it does not establish superior prediction, Atari learning or generality. The
parameter reduction is only about 1%, not a meaningful compute saving.

Training wall times excluding construction were 792 s, 806 s and 851 s;
last-100-update medians were approximately 0.328 s, 0.332 s and 0.355 s.
CPU compilation overlapped part of the second
run, so treat its total wall time descriptively. Construction itself took about
93–98 seconds and is logged separately.

Held-out seed-1 probes use 1,000 random actions and exclude reset targets from
forecasts. All three one-step prior reward heads have AUC 1 on 15 positive events.
Open-loop feature errors are:

| Objective | Horizon 1 MSE | Horizon 5 MSE | Horizon 15 MSE |
| --- | ---: | ---: | ---: |
| Reconstruction | 0.002127 | 0.002151 | 0.002192 |
| Prediction only | 0.003222 | 0.003249 | 0.003292 |
| Auxiliary, forecast head | 0.003192 | 0.003515 | 0.003801 |
| Persist last observed features | 0.008127 | 0.014002 | 0.019210 |

All beat persistence, but neither new objective beats the reconstruction control.
There is no measured reason to retain the auxiliary's 29% extra parameters or
promote prediction-only to the default. The task is small and deterministic;
match the head structure and repeat on harder, action-sensitive sequences before
interpreting this as a verdict on the causal objective.

Artifacts use `runs/kickoff-grid-{control,predictive,auxiliary}-seed0*` and matching
checkpoint directories. Probe cloning is read-only diagnostic evaluation; no
cloned or rewound environment contributes training data.

## Matched spatial objective gate

The corrected runs preserve the same seed, 10k forced-random actions, 188 food,
57 episodes and 2,230 updates. Both objectives use the control's spatial head
and canonical downstream initialization. Only the future trunk excludes the
current posterior stochastic input. Evaluation and held-out probe settings are
unchanged from the pilot.

| Objective | Parameters | Frozen food | Horizon 1 MSE | Horizon 5 MSE | Horizon 15 MSE |
| --- | ---: | ---: | ---: | ---: | ---: |
| Reconstruction control | 836,899 | 2,500 | 0.002127 | 0.002151 | 0.002192 |
| Spatial prediction only | 828,707 | 2,499 | 0.002173 | 0.002186 | 0.002224 |
| Spatial auxiliary | 1,077,859 | 2,499 | 0.002028 | 0.002047 | 0.002091 |

Matching the head removes most of the initial prediction gap. The auxiliary
improves held-out error by about 4.7%, but neither objective improves control
on this nearly saturated task. One training seed and one held-out trajectory
do not establish a general representation advantage. Keep reconstruction as
the default; retain the two causal variants for harder tests.

The auxiliary's independent uniform unrelated-action control has MSE 0.009251
at horizon 1 and 0.019046 at horizon 15, versus 0.002028 and 0.002091 with the
actual actions. The model is using actions, not merely predicting a background.
Diagnostic calls use their own categorical stream and cannot perturb acting.
The corresponding control and prediction-only errors at horizon 1 are 0.009231
and 0.009289, versus 0.002127 and 0.002173 with actual actions. Adding this
diagnostic leaves every previously recorded feature metric exactly unchanged.
An ensuing boundary audit found that the old feature probe also excluded
terminal arrivals before clearing pending forecasts. That diagnostic is corrected;
terminal-inclusive confirmation is recorded separately from these original figures.

Prediction-only and auxiliary training took 706 and 761 seconds, excluding
96 and 102 seconds of construction. These timings include the later cached
posterior-readback optimization, so comparison with the original 792-second
control is not an objective-only speed claim. Frozen evaluations perform zero
learner updates. Artifacts use `runs/kickoff-grid-spatial-{predictive,auxiliary}-seed0*`
and matching checkpoint directories.

## Native AGC and BPTT ablations

The same reconstruction-only, seed-0, 10k forced trajectory is reused for these
single-variable tests: 188 food, 57 episodes, 2,230 updates and 836,899 parameters
in every case. AGC zero disables clipping in both world and behavior optimizers.

| Setting | Frozen food / 10k actions | Construction | Training | Last-100 world-stage median |
| --- | ---: | ---: | ---: | ---: |
| AGC 0.3, BPTT 64 control | 2,500 | 92.6 s | 792 s | 0.1236 s |
| AGC 0, BPTT 64 | 2,500 | 92.7 s | 703 s | 0.1240 s |
| AGC 0.3, BPTT 8 | 2,500 | 5.0 s | 688 s | 0.1190 s |

The new runs include cached posterior readback, so their total-time improvement
over the original control cannot be attributed to clipping or BPTT. There is no
large world-stage speedup here. Short BPTT dramatically reduces construction,

clipping or full BPTT is unnecessary in 12M Atari. Keep that measured recipe.

## Cheap temporal representation probe

The Pong motion probe trains/validates/tests on distinct seeds 10/11/12/13,
512 samples per seed, under the published wrapper. Targets are past one-decision
object displacements, not future motion. History pairs never cross a reset or
a missing object label. The causal representation concatenates current pooled
features with their difference from the preceding decision.

| Representation | Mean held-out displacement R² |
| --- | ---: |
| RGB 64×64 | −0.266 |
| Projected 14×14 | 0.270 |
| Pooled 7×7 | 0.247 |
| Pooled features + causal difference | 0.676 |
| Trained 12M RSSM belief | 0.768 |

History improves ball-y and both paddle displacements, but ball-x R² remains
only 0.173. This supports testing cheap temporal input before porting a much
larger video encoder; it does not establish improved agent learning.
Artifact: `runs/kickoff-pong-motion-probe.json`.

The recovered seed-0 100k Pong agent's 2,560-dimensional recurrent belief reaches
mean R² **0.768**, including **0.608** for horizontal ball displacement. It
does not dominate every target: vertical-ball and player-paddle R² are 0.789
and 0.852 versus 0.809 and 0.901 for explicit history. The recurrent model already
contains useful motion information, including the hardest single-frame cue.
This removes an immediate capacity-based reason to port a video encoder or add
redundant temporal input. It does not settle early-learning sample efficiency
or visual sufficiency in other games.

The probe uses the original `ac3e4f6` backend revisions in an isolated build,
with only a read-only policy-feature getter added. It does not rewrite the
checkpoint's provenance or perform learner updates. Every arrival, including
unlabeled frames, enters recurrence; each held-out seed restores the same frozen
checkpoint afresh. Original RGB/DINO/history results reproduce exactly. Artifact:
`runs/kickoff-pong-rssm-motion-probe.json`; getter-only source patch:
`runs/kickoff-legacy-latent-api.patch`.

## Sparse reward and intrinsic control

Private Eye random control: published wrapper, ALE 0.12.1, seed 0, 20,000 actions
(80,000 nominal frames), seven positive reward events and total game reward 700.
There were seven complete episodes and one partial episode. This is a short
sparsity/integration check, not the final Atari-100k score window.
Artifact: `runs/kickoff-privateeye-random-seed0-20k.jsonl`.

Persistent GridWorld random controls at 10,000 actions, seeds 0/1/2, collect
168/145/125 food and suffer 52/57/60 deaths, with returns 116/88/65. There are
zero harness episode resets.

Agent-controlled reward comparisons use 1M seed 0, the same diagnostic rates as
the native objective pilot, 10k actions and 2,229 updates each. There are no
harness resets. The reconstruction control is fixed at 0.25; the predeclared
intrinsic scale is 0.1. Counts are generated only in the two intrinsic variants.

| Learning reward | Food | Deaths | Game return | Raw intrinsic return | Train time |
| --- | ---: | ---: | ---: | ---: | ---: |
| Extrinsic only | 1,100 | 37 | 1,063 | 0 | 799 s |
| Extrinsic + 0.1 × novelty | 1,116 | 32 | 1,084 | 3,449 | 790 s |
| 0.1 × novelty only | 150 | 60 | 90 | 4,162 | 794 s |

Extrinsic and mixed policies approach the optimal 250 food/1,000 actions late in
training. Their small difference from one seed is not an intrinsic-reward win.
Intrinsic-only is roughly random overall and collects just one food in its last
two 1,000-action windows, with 20 deaths. Its higher novelty return is not better game behavior.
It does not collapse to a single action: all four remain represented. Its 10,001
visits occupy 1,082 hash buckets versus 1,014 for mixed reward, with bucket
entropies 6.26 versus 5.48 nats. It spreads visual visitation more evenly, but
that success against its chosen novelty objective does not establish food
competence. Bucket counts are not counts of semantically distinct game states.
Keep the bonus disabled by default: this is a measured negative exploration
control, and guidance remains necessary on this task. It does not rule out
other intrinsic objectives or other scales. Artifacts use
`runs/kickoff-persistent-{extrinsic,mixed,intrinsic}-seed0*` and matching checkpoints.

The optional novelty implementation has fixed memory, repeat-visit decay and
versioned, checkpointed counts. It consumes only frozen visual features.
The first uncentered hash failed its discrimination smoke: a 2,001-observation
random native stream occupied only five buckets, with 53.4% in the largest.
Centering on a fixed first observation increases this to 637 buckets with 2.6%
in the largest, on the same actions and without learning. The fixed reference
is checkpointed and never drifts. Version-1 counts are rejected rather than
silently reinterpreted under version 2. A matched fixed-left border action
occupies 27 buckets and earns 358 raw intrinsic reward versus 1,300 for the
random walk. It collects no food and dies 19 times. The changing energy bar and
respawns still earn novelty without locomotion; useful exploration remains an
empirical question, not a consequence of better bucket utilization.

Artifacts: `runs/kickoff-persistent-random-seed{0,1,2}-10k.jsonl`,
`runs/kickoff-visitation{,-centered,-idle}-smoke.jsonl` and matching checkpoints.

## Upstream control provenance

The old upstream checkout's `.git` points into a deleted temporary repository;
completed run artifacts remain usable, but it is not a verifiable source checkout.
A fresh checkout at `e3f02248693a79dc8b0ebd62c93683888ddaccfe` is prepared in
`runs/upstream-dreamerv3-source`. Its only patch exposes two wrapper defaults
to Elements' configuration schema and appends the published-wrapper preset
declared in `python/examples/run_upstream_control.py`.

That runner refuses an existing output directory, validates the source diff,
records actual interpreter/packages/command, captures output locally and marks
completion only after a successful process exit. It does not install dependencies
or download games. The existing JAX 0.6.2/CUDA 12 environment is reused. ALE 0.9.0
there differs from Kindle's 0.12.1; learned RGB perception, bfloat16 and upstream
reset-record accounting are also explicit differences.
The first launch failed before training because the two default schema keys
were missing; that failed manifest is preserved separately from the corrected run.

The corrected size12m seed-0 run completed 100,000 driver records in 1,718 s
(28.6 minutes), with 10,498,772 trainable parameters. Its final-window six scores
are −13/−9/−6/−16/−9/−11, mean **−10.667**, versus Kindle's recovered three-seed
mean 0.0. Runtime-specific random-floor adjustment changes the difference from
+10.667 to +10.916 in Kindle's favor. One upstream seed, different perception,
precision, ALE and reset accounting do not establish an algorithmic advantage.
The ROM files themselves match byte-for-byte in both interpreters: Pong SHA-256
`41623e3c26148f96cbe77d56512845d224a63c8fe5bf90e38527155e39ec96d3`.
This removes a game-file difference, not an emulator-version difference.
Upstream policy throughput is about 59 actions/s during steady training; the
Rust learner remains substantially slower even after fixing readback.

Artifacts: `runs/kickoff-upstream-pong-12m-seed0-100k-v2/` and
`runs/kickoff-pong-12m-local-comparison.json`. The score reader validates both
the original 1M manifest and the new runner's exact source/config hash,

## Encoder identity and verification

Native pixel checkpoints previously declared an expected DINO revision without
checking the actual supplied weight file. They now store its SHA-256 and validate
it before GPU construction on restore. Legacy checkpoints without that field
require the pinned reference file. A same-shaped replacement is not accepted as
the same perceptual space. The small SHA-256 dependency serves this guard; no
new encoder abstraction or trainable frontend was added.

The CPU suite passes 78 Rust and 75 Python tests, with both Clippy passes clean.
The updated nine-test GPU suite passes in 87.09 s. A legacy Tiny pixel checkpoint
restores, saves with its fingerprint, and restores again with learner/environment
counters and visitation state unchanged. Artifacts:
`runs/kickoff-gpu-fingerprint-suite.log` and `runs/kickoff-fingerprint-roundtrip.json`.
