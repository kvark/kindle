# BF16 dense split-K qualification

Declared October 12, 2026 before GPU execution. Follow the completed
[JAX gap diagnosis](../results/2026-10-12-jax-gap-accounting.md). No Atari
training, new profiler campaign, precision change or parameter sweep.

Published upstream remains Meganeura `20af998` / Blade `7909fc1`.
Control is the qualified integration `5a493322`, Blade `663afd2`,
Naga `c9fd6a85a`. Use isolated worktrees and preserve neighboring user work.

## One change

Partition long BF16 dense reductions when their 32x32 output grid has fewer
than 128 workgroups. Require K >= 1024, aim for 128 workgroups, cap at 16
partitions and require at least 256 reduction elements per partition.
Unsplit products, fused addends, convolution, grouped products, storage
precision and all learning settings stay unchanged. Keep F32 partials and
sum them with the existing scalar-order SumRows kernel before output rounding.
No atomics or new reduction shader. Invalidate caches whose fourth matrix
parameter predates the partition count. A small-M RGB projection currently
launches only eight workgroups; this addresses that measured underfill.

## Bounded qualification

1. CPU preparation: one CPU, 2 GiB, no swap. Format, CPU selection/cache/shader
   validation and Clippy. Build immutable backend and Kindle executables;
   no compilation during GPU timings.
2. Serialized guarded GPU tests, <=180 seconds per process. Cover ragged
   M/N/K, transposed A/B, F32 and rounded BF16 outputs, unsplit addends,
   poisoned/reused buffers, F32 master and reduced-input gradients. Independent
   F64 checks use the existing reference tolerances without relaxation.
   Binary-fraction hot-shape products must remain exact. Keep unchanged
   connected-learner and convolution BF16 checks.
3. One matched ordinary pair for RGB12M/B8/BF16 and CDP12M/B32/mixed:
   16 warmup + 256 measured synthetic updates, <=600 seconds/process.
   Same initial checkpoint, fixture RNG, model, batch, schedule and backend
   except split-K. No profiler/timestamps. Require exact initial tensors,
   all 272 finite reports/targets and finite initial/first/final tensors.
   Changed reduction order may change later stochastic trajectories; disclose
   that, do not demand bitwise training identity or claim learning equivalence.
   Accept a useful >=3% complete-update improvement in at least one recipe
   with no >2% regression in the other. Do not repeat a failed timing gate.
4. Only if these gates pass, publish the small upstream change and pin the
   qualified integration, then run binding/revision checks and track CI.
   A fast isolated matrix does not qualify an otherwise slower complete update.

Use the existing persistent systemd/host-guard workflow (`Restart=no`,
`KillMode=control-group`, bounded deadlines), expected RTX 5080, driver
580.178.04 and >=2 GiB sampled Vulkan headroom. Record allocation warnings;
other API/numerical faults stop the affected job for review. No CPU quota on
GPU workers, NVML polling, driver recovery or old-queue restart.

## First qualification review

The first GPU oracle stops before any learner timing. The 128x256x2560
product's first partial is -0.414794921875 instead of 1.35009765625: it sums
320 K elements instead of 640. Source inspection finds the native binding
overwrites the fourth uniform with the Y workgroup count (8), not the
declared partition count (4). The smaller first case happened to use 8 for
both. Preserve the failed guard, source and immutable executables.

Fix that mapping in the native binding and add a CPU check distinguishing
BF16 partitions from existing GEMV column groups. No numerical relaxation,
new tile choice or arithmetic change. A corrected immutable build may run
the same full oracle and all previously unstarted checks in a fresh bounded
queue; the ordinary timing pair remains unstarted, not repeated.

The corrected runtime passes all 32 full-product/partial cases (859,216 exact
F64 comparisons). The next check stops in the CPU reference evaluator: the
test constructs an explicit fused addend using a later graph node, which is
valid for the compiler's buffer allocation but not the reference's ordered
walk. Move the test's bias leaf before its consumer and assert topological
order in the CPU test. This is a test-only fix; do not rebuild or change the
qualified runtime/timing binary. Retain both failed guards. Continue the nine
uncompleted checks in a fresh queue, requiring the successful full oracle as
a prerequisite. No tolerance, shape, kernel, timing budget or recipe changes.
